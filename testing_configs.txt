Suggestion
i have an idea that might help us 
We know for sure that the multiple nodes containing the simulator states are creating an issue for us 
and we know that the rollout speed of lets say depth 10 signifianctly faster (1000 to 100x) than forking of a node.

Using this as a guide 
when trying a particular node's action in an iteration after the right selection in MCTS , we can just copy/snapshot the root node
run that trace of MCTS all the way to that node which has been selected by applying the same actions recorded in the MCTS from the root node of both players till we reach that node that has been selected, perform the action etc suggested by MCTS and rollout like we do after the log has been stored as before, go back to the root simulator node and delete this forked node. This way we can have just at any given time 2 simulator nodes atmost while achieving the same speed and 100 to 1000x less memory.
